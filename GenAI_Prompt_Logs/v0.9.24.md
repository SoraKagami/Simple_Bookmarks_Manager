### Investigation result

The likely Auto Scroll failure had two parts:

1. **Auto Scroll was blocked when Chromium reported `prefers-reduced-motion: reduce`.**

  That means users with OS/browser reduced-animation settings could enable Auto Scroll in SBM and still see no scrolling.
2. **The Web Animations API path was too fragile for this feature.**

  Truncate worked because it directly changed the displayed text. Auto Scroll depended on `element.animate()`, so the hover/overflow detection could succeed while the actual movement still failed or appeared not to start.

### Fix applied

- Replaced the Web Animations API Auto Scroll movement with a direct `requestAnimationFrame` transform loop.
- Removed the forced reduced-motion suppression for this explicit SBM option.
- Auto Scroll now creates animation work only for the currently hovered overflowing text element.
- Truncate behavior from v0.9.23 is unchanged.
- The disabled/default mode remains on the v0.9.23 fast path; no Auto Scroll frame loop is active when `Bookmark_TextTruncation = 0`.
