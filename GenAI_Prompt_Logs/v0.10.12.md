[![](https://www.google.com/s2/favicons?domain=https://developer.chrome.com&sz=128)Chrome for Developers](https://developer.chrome.com/docs/extensions/develop/security-privacy/stay-secure?hl=en&utm_source=chatgpt.com)
- **CSP:** good but could be tightened. Current CSP is:

  ```JSON
  JSON"script-src 'self'; object-src 'none'; frame-src 'self'; connect-src 'self'; img-src 'self' data:;"
  ```

  This is already stricter than Chrome’s MV3 minimum for extension pages. Chrome documents that MV3 extension pages require CSP under `content_security_policy.extension_pages`, with remote script disallowed. [![](https://www.google.com/s2/favicons?domain=https://developer.chrome.com&sz=128)Chrome for Developers+1](https://developer.chrome.com/docs/extensions/reference/manifest/content-security-policy?utm_source=chatgpt.com)

  Suggested hardening: test removing `data:` from `img-src` if no UI images require it.
- **iframe Options popup:** acceptable. The embedded Options iframe is same-extension only via `chrome.runtime.getURL("options.html?embedded=1")`, and CSP limits frames to `'self'`. No `postMessage` listener was found.

  Suggested hardening: add a tiny allowlist helper for info/options iframe paths so future calls cannot accidentally pass arbitrary extension-page paths.
- **Context menus:** good. Custom menu items use `<button>` + `textContent`, actions are fixed functions, and user-controlled labels/bookmark text are not injected as HTML. No change needed.
- **URL opening / `chrome.tabs.create`: mostly good, but the main hardening opportunity.** SBM centrally parses URLs with `new URL()` and blocks `javascript:`, `data:`, and `blob:` by default before `chrome.tabs.create()` / `chrome.windows.create()`. Chrome’s `tabs` API docs also confirm the `"tabs"` permission is not required just to use the namespace; it grants sensitive tab metadata access, which SBM avoids. [![](https://www.google.com/s2/favicons?domain=https://developer.chrome.com&sz=128)Chrome for Developers](https://developer.chrome.com/docs/extensions/reference/api/tabs?utm_source=chatgpt.com)

  Suggested hardening: add an optional stricter URL-open mode, or expand default blocking to include `file:` and unknown external-protocol schemes. This is behavior-sensitive because users may intentionally bookmark `mailto:`, browser pages, or app links.
- **Storage/settings parsing:** good. `settings.js` normalizes booleans, enums, numeric ranges, folder IDs, theme/font values, and legacy bool-to-dropdown values before use. This is especially important because `chrome.storage.local` values should be treated as user-controlled.
- **Minor surface to consider later:** `manager.js` exposes `globalThis.SBM_getSessionLogRecords` and `SBM_clearSessionLogRecords` so embedded Options can read/clear in-memory logs. This is same-origin extension-only, not remotely reachable. Suggested hardening: replace with a frozen namespace object or a narrow `postMessage` bridge with explicit origin/source checks, but this is low priority.
