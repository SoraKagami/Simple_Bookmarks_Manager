### Investigation and fixes

**1. Performance degradation with `Bookmark_TextTruncation = 0`**

The main issue was that v0.9.21 still installed Library and Folder Contents `pointerover` / `pointerout` handlers even while the feature was disabled. Those handlers continued doing row detection and scheduling text-effect refresh work.

v0.9.22 now has a strict disabled fast path:

- No text-effect hover listeners are installed in mode `0`.
- No text-effect animation frames are scheduled in mode `0`.
- No clicked/hovered text-effect state is maintained in mode `0`.
- Any existing animation/truncation state is cleaned up when switching back to mode `0`.
- I also removed the extra `sbm-display-text` class from every normal rendered row, returning the default DOM structure closer to v0.9.20.2.

**2. Auto Scroll not working**

The overflow detection was the larger functional bug.

v0.9.21 checked:

`scrollWidth > clientWidth`

That is unreliable for SBM's layouts, particularly Sidebar `LibraryFullView`, because its tree intentionally uses `max-content` to support horizontal scrolling. In that layout Chromium sees the text element itself as wide enough for its contents, even though much of it lies outside the visible sidebar viewport.

v0.9.22 instead:

- Measures the actual rendered text width.
- Calculates the portion of the text element that is actually visible inside the Library or Folder Contents viewport.
- Animates only when the measured text exceeds that visible width.
- Temporarily constrains only the active hovered/clicked text element while the effect is running.

This now works for:

- Normal Library folders/bookmarks.
- Middle-pane bookmark **Title**.
- Middle-pane bookmark **URL**.
- Sidebar `LibraryFullView` folders/bookmarks.

**3. Truncation not working**

The same faulty overflow detection prevented truncation.

The middle truncation path now uses the actual visible width described above, including Sidebar Mode. `0 = Auto` continues to calculate the longest middle-ellipsis representation that fits.

I also replaced the v0.9.21 CSS `:hover` re-query mechanism with direct delegated pointer-row tracking. This is both simpler and more reliable.
