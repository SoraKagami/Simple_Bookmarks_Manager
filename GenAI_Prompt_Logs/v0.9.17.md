### About the existing double-click behavior

The important answer is: **bookmark opening on double-click is hard-coded into SBM, not selected by the OS.**

SBM explicitly attaches `ondblclick` handlers to bookmark rows and calls its own `openOrNavigate()` function. So Windows' choice of single-click/double-click behavior in Explorer does not determine how SBM bookmarks open.

There is one nuance: Chromium/the browser's input-event system determines when mouse/touch input produces DOM `click` and `dblclick` events. So the **action assigned to double-click is SBM's choice**, while recognition/timing of the physical clicks is handled below SBM by Chromium and the operating-system input stack.

This matters for touch. A touchscreen interaction should **not be assumed to behave exactly like a mouse double-click**. Depending on Chromium's gesture handling, device, and input method, double-tap behavior can differ or compete with scrolling/zooming gestures.

For future documentation, I would therefore recommend wording mode `0` as:

> **Disabled (SBM double-click behavior)**

rather than:

> **Disabled (default OS behavior)**

I kept your requested wording unchanged in v0.9.17, but the former would technically describe the implementation more accurately.

The new explicit single-click option is actually helpful for touch users because it removes reliance on a double-click/double-tap gesture.
