## Findings

1. **`Optimisation_TempBookmarkTreeMaps` needs rework.**

  `tempBookmarkTreeMaps()` rebuilds full maps every call, and `rootFolders()` uses it even when only top-level folders are needed. Newer paths such as `renderRoots()`, `visibleTreeItems()`, and keyboard navigation can trigger extra full-tree walks. Also `childFolders(folder, maps)` currently ignores the `maps` argument.
2. **Options page does duplicate work after every save.**

  `saveOption()` updates controls, but `chrome.storage.onChanged` also calls `loadOptions()`, which reloads settings, i18n, and startup-folder bookmarks. This can make Options feel sluggish, especially with large bookmark trees.
3. **Large row renders create many per-row closures.**

  `renderList()`, `renderFolderTreeNode()`, and `renderBookmarkTreeNode()` attach click/dblclick/auxclick/drag/drop handlers per row. For thousands of bookmarks, delegated events from `#list` and `#roots` would reduce memory churn and GC pressure.
4. **Selection changes often do full re-renders.**

  `performSelect()` calls `render()`, and `updateSelectionHighlights()` scans all visible rows. Simple selection changes could update only previous/current rows plus Details.
5. **Search currently renders on every keystroke.**

  `#search.oninput` immediately recomputes visible items and re-renders. Coalescing with `requestAnimationFrame` or a very small debounce should improve typing responsiveness. Browser animation/update work is commonly coordinated with `requestAnimationFrame`; MDN also notes rAF pauses in background tabs/hidden iframes. [![](https://www.google.com/s2/favicons?domain=https://developer.mozilla.org&sz=128)MDN Web Docs+1](https://developer.mozilla.org/en-US/docs/Web/API/window/requestAnimationFrame.?utm_source=chatgpt.com)
6. **Auto-scroll is acceptable but can be lighter.**

  Current hover auto-scroll uses one JS `requestAnimationFrame` loop per active hovered field. That is bounded, but a CSS animation using custom properties for distance/duration would move per-frame work out of JS. MDN notes transform animations can be efficient when composited, while DocumentFragment-style DOM batching is useful but not always a magic performance win. [![](https://www.google.com/s2/favicons?domain=https://developer.mozilla.org&sz=128)MDN Web Docs+1](https://developer.mozilla.org/en-US/docs/Web/Performance/Guides/CSS_JavaScript_animation_performance?utm_source=chatgpt.com)

## Recommended update plan

1. **Fix temp-map optimization first.**

    - Make maps pass-scoped, for example `const maps = Optimisation_TempBookmarkTreeMaps ? buildTempBookmarkTreeMaps() : null`.
    - Pass `maps` into `rootFolders(maps)`, `childFolders(folder, maps)`, `descendantFolders(folder, maps)`, `visibleItems(maps)`, and `librarySearchVisibleIds(maps)`.
    - Avoid building maps inside helper functions repeatedly.
2. **Stop Options self-reload duplication.**

    - Add a local “saving keys” guard or ignore same-page storage changes caused by `saveOption()`.
    - Keep `storage.onChanged` for external changes from Manager/other Options pages.
3. **Optimize selection updates.**

    - Add helpers like `rowForId(pane, id)` and `refreshSelectionRows(previous, next)`.
    - Use full `render()` only for navigation, search, sort, folder expand/collapse, layout/language changes, and multi-select range changes.
4. **Coalesce search input.**

    - Store pending search text immediately.
    - Schedule one render per frame with `requestAnimationFrame`.
    - Preserve current sidebar-search behavior.
5. **Optionally delegate row events.**

    - Start with low-risk click/auxclick/dblclick delegation.
    - Leave drag/drop delegation for a separate pass because it is behavior-sensitive.
6. **Optional auto-scroll CSS pass.**

    - Keep behavior identical, but replace JS per-frame transform updates with CSS animation variables.
    - Keep current JS fallback only if needed.
